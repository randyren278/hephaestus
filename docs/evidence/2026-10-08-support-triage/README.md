# Support-triage preparation, 2026-10-08

The [acceptance pack](../../../examples/support-triage/README.md) has 24 public,
fictional support tickets, a shared explicit policy, two reasonable prose
variants and a World template using strict JSON scoring. Its cases include
precedence conflicts, current versus resolved incidents, staging, Unicode and
instructions embedded in ticket text. The checklist variant is a hypothesis;
no improvement is assumed.

[Actual preparation proof](preparation-proof.json) records a fresh frozen
production daemon, a separate minimal Git source repository, both canonical
manifests, the registered World and both Markdown Genomes. Profile readbacks
agree on model, authority and World, show 12 visible plus 12 sealed tasks and
confirm five-minute trials with a four-hour-and-ten-second aggregate bound.
The daemon replayed 14 events while frozen with no active runs.

Configured provider executables were launch-marker stubs. Neither was invoked.
The syntactically valid model label is an explicit offline placeholder; this
does not establish model availability, authentication or hosted quality. The
250,000-micro-USD ceiling in this proof is profile-test data, not approval to
spend quota or money. No provider credentials were read or configured.

[Actual Claude review](claude-review.txt) checked all 24 labels against the
policy, found no conflicting ground truth and confirmed paired configuration
fairness and the honest public-holdout limitation. Its prompt-filename concern
was addressed by naming the existing body as the checklist prompt. This review
did not run tests or establish real-provider behavior.

Acceptance still needs an operator-selected exact model, authorized provider
usage, actual outputs, protected scoring, canonical Selection, restart/replay
and a checked report. Customer confidence also needs private independently
authored holdouts and representative repeated measurements. The public pack
alone cannot establish broad improvement or product revenue.
