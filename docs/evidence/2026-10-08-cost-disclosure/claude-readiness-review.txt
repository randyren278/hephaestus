- **The CI job is a real gate.** It pins both `rustc` and `cargo` to 1.88.0 through `rustup which` and runs `check --locked --workspace --all-targets --all-features`. Clippy still runs on stable with `pedantic = "deny"`, so no gate got weaker.

- **The `guardian-leader-exit-leaves-descendants-running` mutation still matches the source.** Its `find` text matches the source byte for byte, including the 16-space indent, and its targeted test command is still at `checks.json:12`. Nothing in this evidence shows the mutation was re-run after the edit.
- **`run_result.rs:591-598` behaves the same as before.** The length is checked to equal 128 first, so `as_chunks::<2>()` gives exactly 64 pairs with no remainder.
- **`file_event_store.rs:222-238` has a weakness, low severity.** The odd-length check counts bytes but the decoder walks characters. A field like `<64 hex digits>é` (66 bytes, 65 characters) passes the check, and `as_chunks` silently drops the trailing `é`. If the old code used `chunks_exact(2)`, behaviour is unchanged; if it used `chunks(2)`, the old code panicked here. Hashes are computed from the decoded bytes, so this lets a tampered file decode silently but can't forge an entry. Not caused by the MSRV change. Decoding over `as_bytes()` with an ASCII hex check, like `run_result.rs`, would close it.
- **The other `% 2 != 0` checks** at `runtime_exec.rs:671` and `hephaestus-remote-worker.rs:147` weren't converted. Stable Clippy CI will show whether that matters.
