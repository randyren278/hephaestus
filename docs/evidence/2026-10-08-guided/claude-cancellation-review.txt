**Why it holds:**

- **The guard rejects a newer attempt.** `poll` (`revision.ts:206-207`) reloads the saved recovery cursor and compares its latest evaluation ID with the one on screen. If another attempt has been started, it throws before it fetches a job or builds new state. A poll can no longer quietly swap in a newer attempt.
- **The screen keeps the old attempt when the guard fires.** The poll path in `revision-view.tsx:110-113` only shows the error message, so the confirmation keeps the attempt it was showing. If the user then presses Y, `cancel` (`revision.ts:275`) compares that displayed job with the saved cursor and refuses with "Comparison changed". It fails closed, and no `job_kill` is sent.
- **Polls can't race this app's own actions.** Polls are skipped while an action is running (`revision-view.tsx:106`). Starting an action also bumps `generation`, so an earlier poll that finishes late is thrown away (`isCurrent` at `revision.ts:209` and `active()` at `revision-view.tsx:111`).
