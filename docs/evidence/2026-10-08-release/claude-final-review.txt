## Should fix: a manual dispatch on a tag can't be told apart from the official release

- **Where:** `release.yml:10` and `:201–237` (signing has no event gate), and `docs/RELEASES.md:10–12` and `:49–64`.
- **What happens:** `sign-and-attest` also runs on `workflow_dispatch`. The docs explicitly allow dispatching on a tag ref. That run signs with the identity `…/release.yml@refs/tags/vX` and creates attestations with source ref `refs/tags/vX`. Those are exactly what the documented `cosign verify-blob` and `gh attestation verify` commands accept. So line 63 ("do not accept … a branch rehearsal") only works for branches. A tag rehearsal passes every check. The Intel archive isn't covered by the reproducibility job, so it can produce a different, unpublished digest that still verifies as official.
- **Why "rehearsal" is overstated:** even a branch rehearsal writes public Rekor entries and repo attestations. "Without publishing" is only true of the GitHub Release.
- **Smallest fix (recommended):** in the `version` step (`release.yml:53`), fail when `GITHUB_EVENT_NAME == workflow_dispatch` and the ref is a tag. Then reword `RELEASES.md:10–12`: dispatch runs only on branches, and it still creates public signatures and attestations under a branch identity.
- **Alternative:** add `--certificate-github-workflow-trigger push` to the cosign command. But `gh attestation verify` has no trigger filter, so this only half-fixes it.

## Checked and correct

- **Native architecture acceptance before signing:** the order is version/tag check → `uname -m` check → build → acceptance (with `pipefail`) → checksum → upload. Acceptance tests the exact bytes that get uploaded, and nothing rebuilds them afterwards. If either architecture fails, `build` fails and signing is skipped. `package_macos.py:230,250` also checks single-architecture output with `lipo`.
- **Artifact pattern merging:** `hephaestus-*` matches the two archive artifacts and the two `hephaestus-sbom-*` artifacts. The acceptance logs (`package-acceptance-*`) are excluded. `hephaestus-signatures` only exists after signing, so publish gets it and sign doesn't. File names are distinct per architecture and target (`--target-in-filename`), so merging overwrites nothing. If a glob matches nothing, cosign fails rather than skipping.
- **Prerequisites and publication:** publish needs `sign-and-attest`, which needs `sbom`, so the inventory is a prerequisite indirectly. Publish only runs on a `push` to `refs/tags/v*`, and `contents: write` is limited to that job.
- **Package/SBOM isolation:** the inventory jobs run on Ubuntu with `persist-credentials: false` and no write or id-token permission. They never download the archives. Default features match the default-feature `cargo build` in `package_macos.py:219`. The collector selects only the 7 `BINARIES`, so `hephaestus-evaluator`, `-remote-worker` and `-mcp-gateway` are left out. It fails if a name matches zero or several files.
- **Repo/workflow/tag identity:** `.git/config` confirms `randyren278/hephaestus`. The Fulcio identity format and the `--signer-workflow` / `--source-ref` formats are correct.
- **Docs gate:** no code span in `RELEASES.md` names a missing file.
