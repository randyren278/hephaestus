**Why manual tag runs can't sign under the official identity anymore**
- `sign-and-attest` (`.github/workflows/release.yml:205`) and `publish` (`:250`) both run only when the event is a `push` and the ref starts with `refs/tags/v`.
- A manual run on a tag ref has the event `workflow_dispatch`, so both jobs are skipped. They never get the `id-token: write` permission, so they can't get the OIDC token that would produce a `release.yml@refs/tags/vX` certificate.
- `sign-and-attest` waits on `[build, sbom, reproducibility]` (`:206`). `publish` waits on `sign-and-attest`, so it inherits the same gate.
- On a real tag push, the build fails first if the tag doesn't match the workspace version (`:55-58`). That keeps both jobs from running.
- Signing and publishing don't check out the repo anymore. `build` uses `persist-credentials: false` (`:41`), and so does `sbom` (`:123`).
- `docs/RELEASES.md:10-14` matches this: manual runs build, accept, inventory and check reproducibility, but never sign, attest or publish, even on a tag. The docs require Cosign 3.1.3 (`:35`, `:44`), the same version pinned at `:225`.
