# Ledger hex repair review

I found no new defects and no missing regression coverage that matters. Everything below was checked by reading files only; I ran nothing.

## The fix (`crates/hephaestus-ledger/src/file_event_store.rs:222-245`)
- **Check order:** the odd-length check still runs first (line 223), then the new `value.is_ascii()` guard (228). After both pass, the string is ASCII with an even length, so `as_chunks::<2>()` never has leftovers. That leftover was where a trailing Unicode character used to be silently dropped.
- **Nothing valid is lost:** `to_digit(16)` still accepts uppercase hex. Payloads are stored as hex, so any binary or UTF-8 payload still round-trips. All three fields (payload, previous hash, hash) go through this one function (190-192), so the fix covers all of them.
- **Odd-length Unicode is still handled:** a 3-byte character like `€` gives an odd byte length and was already rejected by the first check.
- **Rust 1.88:** `as_chunks` became stable in 1.88 and `is_multiple_of` in 1.87, so both fit the stated minimum.

## Tests (`tests/file_ledger_durability.rs:370-444`)
- **Rejection test:** 3 fields × {`é`, `🛠`}. Each case requires `MalformedRecord` and an unchanged complete file. All six cases would have failed before the fix, because the dropped character left the bytes and hashes unchanged.
- **Compatibility test:** replays a `Café 🛠` payload with uppercase hex and checks it matches the original event exactly. One small gap: this ledger has only one event, so its `previous_hash_hex` is probably the all-zero hash. Uppercasing that changes nothing, so this field isn't really tested with letters A-F. Payload and `hash_hex` are. This doesn't matter much, since all three use the same decoder.

Lines 53-54 explain why the symlink must be resolved. `PILOT_GUIDE.md` points to this pack and doesn't repeat the command.
- **`evaluator-resolution.txt`:** gives one summary sentence per alias (source and package) rather than raw command output. Neither line shows the original symlink path next to the resolved one.
- **`evaluator-path-acceptance.json`:** shows a real offline Arena evaluation, a Selection and a replay (`events=329`), using the **package** evaluator only. The source alias has the resolution line but no Arena/Selection/replay run of its own.
- **Promotion fields:** the Selection receipt has `invariant_gate_verified: false` and `promotion_eligible: false`. That's correct for a run that records a Selection without promoting. It should be called a recorded Selection, not a promotion.
- **Ambiguous placeholder:** line 90 uses `artifact put <installed-reference-evaluator>` without saying whether to pass the symlink or the resolved path. If `artifact put` follows symlinks this doesn't matter. I couldn't confirm that by reading.
