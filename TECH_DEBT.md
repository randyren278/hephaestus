# Technical debt

Debt deliberately deferred so roadmap functionality can land first. Each entry says what was deferred, why, and what paying it down means. Close an entry by linking the commit that resolves it.

| ID | Area | Debt | Why deferred | Paydown |
|---|---|---|---|---|
| TD-1 | Test gates | The per-module coverage floor in `checks/checks.json` was lowered from 95% to 80% on 2026-09-25. | The owner prioritized full roadmap functionality over coverage. The `crates/hephaestus-control/src/server.rs` floor kept blocking merges: it measured 94.4–94.9% after each lane landed. | Restore `coverage_floor` to 95.0 once every critical module measures at least 95.5%. Start with `crates/hephaestus-control/src/server.rs` (94.6% at 060224b) and `crates/hephaestus-control/src/evolve.rs` (83.7%, not yet a critical module). |

| TD-12 | MCP gateway and remote workers | `hephaestus-mcp-gateway` and `hephaestus-remote-worker` are proven by in-process tests plus one manual smoke run against a live daemon. Only a direct reference run can be leased remotely. Worker-to-daemon trust relies on owner-only Unix sockets (no TLS). | Owner speed directive. | Add spawned-daemon E2Es for the MCP JSON-RPC framing, duplicate delivery, and expired credentials. Add mutation entries and a CI job. Support leasing Arena trials. |
| TD-13 | Storage backends | `hephaestus-ledger`'s `EventLedger` and `ArtifactBackend` traits pass a contract suite, but `ControlPlane` still calls the SQLite/CAS stores directly, and no second backend exists. | Migrating every call site would have conflicted with the other lanes. | Route `ControlPlane` storage through the traits, then add a second backend that runs the same contract suite. |
| TD-14 | Meta-evolution | `hephaestus meta evaluate` blocks its connection until every lineage run finishes, with no progress polling. `mutation_prioritization`, `candidate_count`, and `gene_selection` are recorded but have no effect, because Forge proposes only the reference-operation flip. There is no TUI screen, daemon E2E test, mutation entry, or coverage run for `crates/hephaestus-control/src/meta_evolve.rs`. | Owner speed directive; the missing knobs depend on a richer mutation engine. | Make meta evaluation an async job with status polling, wire the strategy knobs into Forge once it has more than one mutation, and add a TUI screen plus E2E and mutation coverage. |
| TD-15 | Provider Arena | Provider Genomes in `submit` and `arena evaluate` are proven offline against fake CLIs in-process only, with no daemon E2E, mutation entries, or coverage run. The reference worker is still pinned for every Arena admission, including all-provider pairs. | Owner speed directive. | Add a daemon E2E for a mixed pair, add mutation entries for `allow_mixed_environments` and the `provider-v1` identity checks, and pin the reference worker only when a role needs it. |
| TD-16 | Replay verification | Projection refresh in a running daemon caches verified evidence by event chain hash (`EvidenceCache` in `crates/hephaestus-control/src/server.rs`), so an artifact blob in the CAS that is tampered with after its event was verified is not detected until the next daemon start or `replay`. Ledger tampering is still caught on every refresh, because the hash chain is re-verified first. | Before the cache, every refresh re-verified all evidence and replayed the whole ledger once per evidence event, so each daemon step cost grew with history size: a refresh took 1.3 s at 139 events, and meta-evaluation runs spun for minutes. | Re-hash cached artifact blobs cheaply, or have the arena crate verify from an already-replayed history instead of reopening stores per event, so a full refresh stays linear without a cache. |
