| TD-16 | Replay verification | **Partially closed in this lane; `EvidenceCache` is kept.** `hephaestus-arena` gained history-borrowing `_in` verification entry points (`load_operator_evaluation_in`, `verify_selection_event_in`, `verify_reference_output_invariant_event_in`, `verify_cluster_event_in`, `load_recorded_evaluation_in`, backed by a new `hephaestus_ledger::EventIndex`) that verify against a caller-supplied, already hash-chain-verified history and the daemon's already-open artifact store instead of reopening stores and replaying the ledger per event, so a *full* verification pass (a cache miss, daemon startup, or explicit `replay`) is now linear in history size instead of quadratic. Measurement showed that removing `EvidenceCache` outright made `meta_evaluate_shows_a_descendant_strategy_reaching_equal_champions_at_lower_cost` alone take over 600 s (versus ~370 s for the entire 123-test control suite beforehand), because `refresh_projection` runs many times as history grows and summing a linear pass over each of those refreshes is still quadratic in the total event count. `EvidenceCache` was therefore kept, now layered on top of the cheaper linear verifiers, so a warm refresh still skips already-verified events at O(1) per event and a cold path (a new event, startup, or `replay`) is linear rather than quadratic. The original limitation is unchanged: an artifact blob in the CAS tampered with after its event was cached is not re-detected until the cache is cleared (daemon restart or `replay`); the ledger hash chain itself is still independently re-verified on every refresh via `EventLedger::replay_verified()`, so a rewritten ledger row is always caught immediately. | Before this lane, every refresh (cache hit or not) reopened `EvaluationStores` and replayed the ledger multiple times per evidence event, so even a cache *miss* cost grew superlinearly with history: a refresh took 1.3 s at 139 events, and meta-evaluation runs spun for minutes. | Remaining: close the CAS-tamper detection gap without reintroducing the quadratic blowup — e.g. invalidate a cached entry when its artifact content hash last-verified digest is cheap to recheck, or periodically force a bounded number of cache entries to fully re-verify each refresh. |
