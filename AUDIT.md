## Progress since baseline

- The domain vocabulary and lifecycle are executable, versioned, and fail closed.
- The canonical SQLite event ledger and BLAKE3 artifact store persist and verify real on-disk state.
- Strict Genome and World compilers normalize JSON/YAML, resolve ancestry and artifacts, constrain authority, enforce exact World comparability, and retain the normalized authorized mutation scope for future Forge enforcement.
- The runnable daemon and CLI enforce a single writer, owner-only authenticated IPC, persistent operator freeze/kill state, Genome inspection, and verified replay.
- The offline reference runtime exercises isolated worktrees, lifecycle operations, expiring capability tokens, and hard output/authority failure paths. A provider-neutral local process supervisor independently enforces allowlisted environments, stdin prompts, process-group interrupt, and hard wall/output limits. macOS hosted commands are wrapped in a live-tested deny-by-default Seatbelt policy; unsupported hosts fail closed. Codex and Claude Code adapters are now real, executable `RuntimeAdapter`s (`SupervisedRuntime::provider`/`provider_guarded`), invocation flags pinned to the current documented CLI contracts (docs/RUNTIMES.md cites sources) rather than guessed, and are wired into the daemon's `run` and synchronous `RunEvaluation` paths: a registered Genome with `model.provider: codex|claude` executes through the same sandbox/budget/evidence pipeline as the reference worker, its NDJSON stream is mapped to a signed run result (final answer as stdout, reported cost bounded by the Genome's World Law, tool calls/denials/cost as evidence traces), and stdout/stderr are redacted before persistence. `submit` (the async job path) and `arena evaluate`'s paired trial execution now admit a provider Genome too: each canonical projection (`JobRecord`/`ArenaJobRecord`) accepts a versioned `provider-v1.<digest>` environment identity bound to the exact configured executable, alongside the existing `reference-v1.<digest>` shape, and bounds the cost budget by the Genome's registered World Law instead of a fixed zero. A paired Arena trial may mix a reference-worker role with a provider role only when the World's Law sets `allow_mixed_environments`; the admission record and the sealed per-evaluation receipt then carry both environments, and the receipt's `schema_version` bumps from 2 to 3 to do so, while every previously recorded homogeneous receipt keeps schema 2 and still verifies byte-for-byte. This is proven fully offline against fake `codex`/`claude` scripts (a mixed paired Arena evaluation through the daemon in-process, selection over it, replay, and a cancelled provider `submit` job); no test, CI job, or mutation run invokes a real provider CLI, spends quota, or touches the network. A real local task against a live-installed `codex`/`claude` CLI has not been demonstrated; docs/RUNTIMES.md documents the exact opt-in steps and required `HEPHAESTUS_LIVE_PROVIDER_SMOKE=1` marker for a user to run that themselves.
- The Experience Plane records the full observable trace vocabulary as bounded redacted CAS artifacts with safe ledger receipts. `RecordedRuntime` binds real adapter lifecycle, checkpoints, failures, provider-visible events, latency, and known deterministic cost to immutable run/Genome/World provenance, failing closed when required start or resume evidence cannot persist. Structured observations, hypotheses, evidence, and contradictions require verified source events and exact provenance; every lesson remains explicitly unverified and cannot become a Gene here. A trusted, non-caller-constructible Experience capability now rehydrates redacted fields from canonical receipt and CAS bytes, recursively validates earlier source events and evidence artifacts, and binds the result to the exact verified event hash after restart.
- The runtime trust checkpoint requires every supervised external launch to traverse the detected OS isolation policy, records adapter-owned completion reasons and elapsed time, reserves terminal evidence capacity, and retains failed containment and unpersisted observations for retry. The gate held a 95% per-module floor across 31 production-critical modules at that point; it is temporarily 80% (see TECH_DEBT.md) and uses branch coverage only for modules with branch records, falling back to lines otherwise. The mutation ratchet includes Arena selection, daemon history verification, and Python histogram invariants in this change.
- The production daemon now composes the registered World/Genome, read-only deterministic runtime, sandbox, evidence wrapper, ledger, and CAS behind `hephaestus run <genome-id>` and the typed `hephaestus evaluate` path. Real daemon/CLI tests verify freeze and budget gating, runtime-owned task/input/seed/environment/budget provenance, signed-result replay, anchored verifier continuity before the first result, exact authenticated Arena consumption after restart, output and trace artifact hashes, sandbox cleanup, terminal projection, and replay after restart.
- The measurement-only Arena now accepts task plans made solely of daemon-signed runtime-result event IDs, resolves their Genome/World/source/output provenance from verified history, enforces exact World-committed task input plus seed/environment/budget pairing, re-hashes and launches the World-bound evaluator in a separate offline bounded worker, validates its canonical request-bound aggregate response, exposes a visible-only summary without the sealed operator event hash, and records deterministic idempotent evaluator receipts. World-bound manifest bytes rehydrate only through strict schema, constructor, visibility, and byte-exact canonical checks; an operator-only scheduling view exposes visible or sealed task IDs and inputs without expected outputs. The daemon now loads the complete task sets itself, pins one revision, launches parent and candidate trials through separate supervised offline processes and private worktrees, validates the evaluator before spending candidate work, cleans all private roots, and makes identical retries reuse authenticated events. Arena retains authenticated terminal failures as unreliable and incorrect rather than discarding them, aggregates correctness, reliability, cost, and latency without overflow, commits each run event hash into evaluator-owned evidence, and mints operator-only aggregate selection evidence bound to the exact evaluation event hash. That evidence rehydrates byte-identically from verified history after restart without exposing task identities, task order, expectations, outputs, trace addresses, or raw store access. `arena select <evaluation-id>` now recomputes the fixed-seed histogram bootstrap and measured Pareto/effect/cost gates from that trusted capability and the exact compiled World, then writes a canonical BLAKE3-addressed receipt referenced by a deterministic event. Exact retries and history verification compare the recomputed receipt bytes and complete canonical event. The receipt names correctness losses separately from invariant regressions; because selection does not consume the separate World-bound output-invariant receipt, it records the invariant gate as unverified and never marks promotion eligible. The Python histogram analysis matches Rust's canonical order and floor rounding and rejects unsupported confidence 10000 and bootstrap work over 20 million draws. Automatic failure clustering, invariant authorization, promotion, and rollback remain pending; Forge currently supports only the operator-directed one-prompt proposal slice described above.
- Selection's Pareto gate now tolerates measured wall-clock latency noise instead of comparing it strictly: a candidate's total latency only counts as a regression once it exceeds the parent's by more than `max(10% of parent latency, 50ms * paired task count)`, a fixed noise floor that also holds on cheap, fast Worlds where the proportional term alone would be too small. This closes a real defect where a strictly-better candidate was randomly rejected for running a millisecond or two slower on trivial reference tasks. The new algorithm identity (`histogram-bootstrap-pareto-tolerant-v2`) applies only to newly recorded selections; recompute dispatches on each already-recorded receipt's own `algorithm` field, so a receipt written under the retired strict comparison (`histogram-bootstrap-v1`) still verifies byte-identically on replay.
- The first operator-directed Forge proposal slice now consumes an exact verified selection event and registered candidate, records a bounded explicit hypothesis, flips exactly one supported agent.prompt operation, and compiles/registers the child through the ordinary Genome compiler. A single `forge.proposed` event binds the source selection hash, parent/child lineage, hypothesis, and prompt CAS addresses; startup and Replay revalidate it. Proposal retries are idempotent, conflicting reuse fails closed, and `promotion_eligible` remains false. Aggregate selection receipts do not contain task-level failure clusters, so hypothesis selection remains operator-authored and no automatic clustering or promotion claim is made.
- `hephaestus evolve` runs unattended, budget-bounded evolution in the daemon through the ordinary Arena, Forge, invariant, and Champion policy, with durable replay-verified `evolution.*` events; freeze halts it and a promotion claim must cite matching evidence. It is proven in-process for three generations with the deterministic reference runtime, and `hephaestus evolve coding --budget <n>` is a CLI convenience that registers the bundled `examples/gauntlet/coding` World and its parent/candidate Genomes against the connected daemon and drives the same 3-generation run to completion (proven by an in-process test that reads the real bundled fixture files). The Gauntlet's seven named failure modes (context loss, premature completion, schema drift, bad routing, duplicate subagents, poisoned memory, hallucinated verification) are now each a real deterministic reference-worker operation pair (`crates/hephaestus-runtime/src/reference_instruction.rs`): a "bad" operation exhibits the pathology on a crafted structured-JSON scenario and a paired "fix" operation avoids it, proven per mode via real Arena evaluate/select (`examples/gauntlet/<mode>/`, `hephaestus-control`'s `gauntlet_failure_modes_reject_the_bad_operation_and_pass_the_fix` test). These are honest, bounded proxies for each pathology's shape, not a real multi-turn model, tool schema, router, subagent orchestrator, memory store, or self-reporting model, and they are reachable only through direct Arena evaluation: Forge's mutation operator (the only thing `evolve` can propose) still knows how to flip solely between `identity`/`ascii_uppercase`, so `evolve` cannot yet discover a fix for any Gauntlet mode on its own. No sealed-holdout statistical improvement is claimed; see [examples/gauntlet/README.md](examples/gauntlet/README.md).
- Failure-cluster analysis (`forge analyze`) groups a candidate's failed trials from a verified evaluation into deterministic clusters by completion reason, budget exhaustion, and visible-task output shape, with explicit hypotheses and the single supported mutation per cluster when one exists. Sealed tasks contribute counts only. The `forge.clustered` receipt is idempotent and recomputed on replay, and `genome propose --analysis --cluster` binds it into a proposal. The only supported mutation remains the reference-operation flip, so clusters needing any other change report no suggestion.
- Champion transitions are now operator commands with a deterministic policy. `champion seed` bootstraps a World's first Champion. `champion promote` requires a `metrics_passed` Forge assessment whose parent is the current Champion, plus a verified invariant receipt for the same evaluation with regressions within budget and a satisfied candidate contract. `champion rollback` restores the previous Champion and quarantines the replaced one. Each transition is one idempotent `champion.transitioned` event that binds the prior transition's hash; startup, replay, and projection refresh recompute it from the history before it. Promotion and seeding are refused while frozen, and rollback is allowed. Rollback can also now be triggered automatically by a canary's live-regression check (below), calling this exact same transition rather than a second implementation of it.
- The mutation runner now gives each suite an isolated process group, escalates and verifies descendant termination on timeout or interruption before restoring source, bounds final pipe draining, honors explicit command overrides, and reports every effective command and timeout. Deterministic tests cover silent grandchildren, escaped pipe holders, interruption, and byte-exact restoration.
- Hosted mutation CI splits the runtime controls by source module, preserving the exact 41-target ratchet while preventing one long serial shard from exhausting a runner.
- Genome and World registration now replays through one trusted projection, `RegisteredObjects`, instead of ad-hoc maps in the control server: acyclicity is enforced by replay order (a parent must already be registered under the same World), payloads must round-trip to exact canonical JSON, artifacts must be byte-exact compiler output, and any violation fails daemon startup. The same projection backs live operator registration: `hephaestus arena manifest`, `artifact put`, `verifier`, `world register|list|show`, and `genome register|list|show` make the product usable end to end without touching the ledger by hand. A real-binary CLI test and `scripts/quickstart.sh` drive the full loop (register, run, paired Arena evaluation, replay, crash, recovery); the manifest now declares 343 mutations across 37 production-critical modules.

- If the scorer thread cannot launch after all paired trials have been signed and persisted, the daemon appends an interrupted Arena terminal and releases the active slot only after that append succeeds. The job has no evaluation receipt; if terminal persistence fails, the daemon returns an error and leaves the active scoring projection intact for recovery.

## Remaining product loop

A hosted-provider adapter now exists for `run`/`RunEvaluation`, `submit`, and `arena evaluate` (see above), but no provider-native tool/context/memory event parser goes beyond the NDJSON mapping already documented, and mixed-environment Arena pairs are opt-in per World rather than the default. Meta-evaluation can compare two Evolver strategies' declared generation/budget knobs over held-out lineages with a bootstrap confidence interval, but because Forge still proposes only the one reference mutation, it cannot yet show a real efficiency improvement from a richer strategy. Drift and staged canary rollout, including automatic rollback on a live post-completion regression, are implemented and tested (see above), but an operator still chooses the candidate and starts the canary; there is no automatic drift-to-canary triggering. The Gene Bank's first slice (extraction, transfer, contradiction, speciation) exists and is tested end to end, but a created species does not yet change how the daemon evolves. There is still no automatic mutation engine beyond the single reference-operation flip, public benchmark, or autonomous evolution loop. The current Ink TUI and the read-only web console are partial operator surfaces: both now expose drift, canary, and meta-evaluation screens, but neither exposes an MCP-call or remote-worker-job activity view, since the daemon has no list command for either (only lookup by known credential/job ID). The MCP gateway and remote worker execution described above are first slices: one job kind can be leased remotely, a second storage backend does not exist, and neither has been driven end to end against a live daemon process outside in-process tests. The deterministic reference run and protected paired Arena plus its non-authorizing measured-selection receipt are trust-substrate tracer bullets, not a hosted-model or autonomous-improvement claim.

The repository is therefore a runnable local trust substrate with one real non-billable execution path, not yet the evolutionary product described by the full plan. Later application layers remain unclaimed until their own product-path evidence exists.

## Audit conclusion

Keep every existing implementation feature. The immediate priority is a trustworthy local Arena and evaluator boundary, followed by one complete local evolution loop before population intelligence, distributed execution, or web surfaces.
